Role & System

담당 역할 & 아키텍처

Spring 서버가 게시글을 관리하고, 추천 · 태그는 FastAPI AI 서버에 요청합니다. 두 서버는 EC2에서 Docker 컨테이너로 실행됩니다.

  1. 게시글 APICRUD · 동적 검색 · 커서 페이지네이션
  2. AI 서버 연동작성 시 키워드 · 임베딩 요청, 추천 요청 중계
  3. 서버 환경 · CI/CDDocker 이미지 → Docker Hub → EC2 자동 배포
  4. 프론트엔드게시글 목록 · 작성 · 상세 화면

Backend

게시글 API · AI 서버 연동

게시글 도메인(작성 · 조회 · 검색 · 추천 요청)을 Spring Boot로 구현하고, 팀원이 만든 FastAPI 추천 서버와 연결했습니다.

KEY POINT

AI가 실패해도 글은 저장

AI 전처리 호출이 실패하면 키워드 · 임베딩 없이 원문만 저장하고 로그를 남김

AI 서버 장애가 핵심 기능(글 작성)을 막지 않음

API

게시글 작성작성 + AI 전처리
게시글 목록검색 · 필터 · 커서 페이징
게시글 상세단건 조회
추천 요청AI 서버로 중계
태그 생성AI 태그 요청

01게시글 작성 흐름

  1. 작성 요청사용자
  2. PostService게시글 생성
  3. AiServiceAI 서버 호출
  4. FastAPI 서버키워드 · 임베딩 추출
AI 응답 성공원문 + 키워드 + 임베딩을 MongoDB에 저장
AI 응답 실패원문만 저장 · 로그 기록 → 글 작성은 정상 완료

추천 · 태그 알고리즘(FastAPI)은 AI 담당 팀원이 구현했고, 저는 Spring에서 호출 · 결과 저장 · 실패 처리를 맡았습니다.

02게시글 검색 — 조건을 조합하는 동적 쿼리

검색어제목 또는 본문에서 대소문자 구분 없이 검색
게시판 타입'전체'가 아니면 타입 조건 추가
태그선택한 태그를 모두 포함하거나 카테고리 일치
커서 페이지네이션마지막으로 본 글 다음부터 최신순으로 조회

03커서 기반 조회 흐름

  1. 첫 요청최신 글 N개
  2. 다음 요청마지막 글 id 전달
  3. 그다음 글부터N개 조회
왜 커서 방식?

마지막으로 본 게시글 다음부터 조회해서, 목록이 길어져도 앞쪽을 건너뛰는 비용 없이 다음 페이지를 가져옵니다.

Deploy — 트러블슈팅

배포 자동화와 트러블슈팅

main에 push하면 이미지를 빌드해 Docker Hub에 올리고, EC2에서 받아 실행하는 파이프라인을 직접 구성했습니다.

CI/CD 파이프라인

  1. main pushGitHub
  2. GitHub ActionsGradle 빌드
  3. Docker HubSpring · AI 이미지 푸시
  4. AWS EC2compose pull · up

DB URI · JWT · OpenAI 키는 GitHub Secrets에 두고 배포 시 컨테이너 환경변수로 주입

KEY POINT

설정은 코드 밖으로

로컬과 운영에서 달라지는 주소 · 시크릿을 환경변수로 분리

같은 이미지가 어느 환경에서나 동작

환경별 설정 분리

로컬 실행AI 서버 = localhost
운영 (EC2)AI 서버 = moida-ai

같은 이미지, 환경변수만 다르게

트러블슈팅

문제원인해결
배포 후 AI 태그 · 추천만 동작하지 않음
Spring이 localhost로 AI 서버를 호출 — 컨테이너 안의 localhost는 자기 자신
Compose 서비스명(moida-ai)으로 통신하고 주소를 환경변수로 분리
AI 컨테이너 기동 실패
uvicorn 실행 모듈 경로가 컨테이너 폴더 구조와 불일치
실행 모듈 경로를 폴더 구조에 맞게 수정
운영 컨테이너에 JWT 시크릿 누락
배포 스크립트의 환경변수 목록에 JWT 시크릿이 빠져 있음
GitHub Secrets에 등록하고 배포 시 주입
