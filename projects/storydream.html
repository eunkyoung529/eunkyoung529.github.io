Overview

프로젝트 개요

아이 눈높이에 맞춰 동화를 읽어주고, 집중이 흐트러지면 말을 거는 AI 동화 기기

어휘 수준에 맞지 않는 동화와 단방향 전자책 때문에 아이들의 독서 흥미가 떨어진다는 문제에서 출발했습니다. 동화를 단계별 난이도로 재구성하고, 집중 상태에 반응하는 양방향 상호작용을 만들었습니다.

Role & System

담당 역할 & 아키텍처

라즈베리파이 기기가 Spring 서버와 AI 서버를 호출하는 구조입니다. Spring 서버의 인증 및 리포트 도메인과 기기 쪽 AI 및 HW 연동을 맡았습니다.

  1. Spring BootJWT 인증, AI 독서 리포트 생성 · 조회, 예외 처리
  2. FastAPI AI독서 기록을 받아 보호자용 요약 코멘트 생성
  3. AI 파이프라인난이도 조절 LLM, 삽화 생성, 집중도 감지 모델
  4. 라즈베리파이 기기Realtime 캐릭터 대화, LED · 엔코더 연동

Backend — 설계 판단

AI 독서 리포트 생성

독서가 끝나면 집중도 · 퀴즈 기록을 모아 LLM이 보호자용 리포트를 씁니다. 느리고 실패할 수 있는 AI 호출이 독서 기능을 막지 않도록 Spring에서 구조를 나눴습니다.

KEY POINT

독서 기능과 AI 리포트를 분리

독서 완료는 즉시 응답하고, 리포트는 트랜잭션 커밋 후 별도 스레드에서 생성

AI가 느리거나 실패해도 독서 기록은 안전

01리포트 생성 시점

독서 완료 API에서 바로 생성LLM 응답 시간만큼 화면 대기
커밋 전에 이벤트 처리저장 전 데이터 조회 · 롤백 시 불일치
→
선택커밋 후 비동기 이벤트트랜잭션 커밋 후 전용 스레드풀에서 생성

02AI 장애 대응

예외 처리 없이 두기리포트가 '생성 중'에서 멈춤
실패 상태로 기록 (초기 구현)실패 리포트는 목록에서 사라짐
→
선택기본 문구로 완료 처리AI 코멘트만 대체하고 집중도 · 퀴즈 지표는 제공

03리포트 조회 쿼리

연관 엔티티 지연 로딩리포트마다 추가 쿼리 발생 (N+1)
전체 기록을 불러와 계산주간 통계를 애플리케이션에서 반복 계산
→
선택Fetch Join · 집계 쿼리연관 데이터를 한 번에 조회, 주간 통계는 DB에서 GROUP BY

EXPLICIT MEMORY

이전 장면 맥락을 요약해 전달

지금까지의 이야기, 현재 장소, 등장인물, 직전 구도를 짧게 요약해 다음 장면 프롬프트 앞에 넣음

장면이 바뀌어도 배경과 상황이 이어짐

Realtime

캐릭터와의 실시간 대화

집중이 흐트러지면 방금 읽은 내용으로 질문하고, 답을 판정한 뒤 이야기를 이어갑니다.

  1. 집중도 저하YOLO 감지
  2. 질문 생성text · JSON
  3. 질문 발화audio
  4. 답변 대기server VAD
  5. 정오 판정text · JSON
  6. 정답 O / X피드백 · 표정
  7. 버퍼 확인audio
  8. 이어 읽기멈춘 지점부터
  1. WebRTC 스트리밍요청–응답 왕복 대신 음성 입출력 스트리밍
